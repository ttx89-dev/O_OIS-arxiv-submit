## Building

The host shell has no TeX binaries. The toolchain lives in the distrobox
container `fedora-toolbox-43` (TeX Live 2023): `pdflatex`, `latexmk`, `bibtex`
verified at `/usr/bin` inside the container. Distrobox shares the home
directory, so paths match the host exactly.

Probe-verified fact: `podman exec fedora-toolbox-43 bash -lc 'command -v
pdflatex latexmk bibtex'` resolves all three; `pdflatex --version` reports
pdfTeX 3.141592653-2.6-1.40.25 (TeX Live 2023) — byte-identical with the
`main.log` engine line of the frozen build:

```
This is pdfTeX, Version 3.141592653-2.6-1.40.25 (TeX Live 2023)
(preloaded format=pdflatex 2026.11.3)  5 NOV 2026 10:50
```

Documented rebuild procedure (enter the container, then build from this
directory):

```sh
podman exec -it fedora-toolbox-43 bash   # or: distrobox enter fedora-toolbox-43
cd ~/Documents/projects/arxiv_submission
make pdf
```

A rebuild reproduces *content*, not bytes (embedded `CreationDate` and engine
release lines differ). Per the `VERSIONS.md` policy: the delivered bytes are
pinned by the v1 identity block; a build that changes `main.pdf` becomes a
candidate new version, never an edit of v1.
